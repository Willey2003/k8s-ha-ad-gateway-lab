Home Lab Kubernetes platform: architecture, access and permissions

Hi all,

The LAB lab Kubernetes cluster has been rebuilt into a highly available, backed-up platform that everyone can log into with their Active Directory account. This note covers what was done, how the platform is built, who can do what, and how to get started.

  • Log in with your AD account: ssh <ad-username>@bastion.corp.example, then use kubectl. There's nothing to request or install.
  • Everyone gets read-only access to the whole cluster, plus their own space to experiment (the playground namespace).
  • Publish a test app at https://<name>.apps.corp.example in minutes, with HTTPS already set up.

What a lab user can and cannot do

CanCannot
  • List and inspect pods, deployments, services, events and logs in any namespace
  • Create, change and delete deployments, services, config maps, secrets, jobs and HTTP routes in playground
  • Publish apps at <name>.apps.corp.example
  • Change or delete anything outside playground
  • Read Secrets outside playground
  • Create namespaces, or touch nodes or cluster settings
  • Run privileged pods or use NodePort / LoadBalancer services

Playground limits: 4 CPU / 8 GiB memory requested (8 CPU / 16 GiB limits), 30 pods, 5 persistent volume claims, Pod Security "baseline". Containers get sensible defaults (0.1 CPU / 128 MiB) if none are set.

4. How to access with your AD account

  1. SSH to the Bastion with your AD username and password. Any SSH client works (Windows ssh, PuTTY, SecureCRT):
    ssh firstname_lastname@bastion.corp.example
  2. kubectl is set up automatically on your first login, with playground as your default namespace.
  3. Run any command, for example kubectl get pods -A. It asks for your AD password once, then stays logged in: you're asked again after 24 hours without use, or after 7 days at most.

Publish a test app

Create a Deployment, a Service and an HTTPRoute in playground for <name>.apps.corp.example, attached to gateway apps in namespace haproxy-unified-gateway. No DNS or certificate request is needed. Working example: kubectl -n playground get httproute hello -o yaml, live at https://hello.apps.corp.example.

Trust the lab certificate (one-time, no admin rights needed)

Lab HTTPS certificates are issued by our own "Home Lab Root CA". Trust it for your Windows user to avoid browser warnings. In Command Prompt:

scp <ad-username>@bastion.corp.example:/etc/kubernetes-ad/lab-ca.crt %USERPROFILE%\lab-ca.crt
certutil -user -addstore Root %USERPROFILE%\lab-ca.crt
